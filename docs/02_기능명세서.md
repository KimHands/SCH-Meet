## 3. 기능별 상세 (필수 기능만 상세 작성)

### B-01 소셜 로그인

- **트리거 (프론트 요청):** 프론트엔드에서 구글 로그인 연동 완료 후 인증 토큰(OAuth ID Token)을 백엔드로 전송할 때 호출
- **제공 API:** `POST /api/auth/login/`
- **입력 데이터:** `{ "id_token": "string (구글 발급 토큰)" }`
- **성공 시 처리 (Response):** `200 OK` 또는 `201 Created`. 구글 공개 키를 통해 토큰 유효성을 검증하고 이메일 정보를 추출함.
  - 가입 이력이 있는 유저: 유저 식별값으로 서버 전용 JWT(Access 및 Refresh Token) 발급 후 응답 반환
  - 신규 유저: 유저 정보 DB 적재(회원가입 처리) 후 신규 유저 여부 플래그(`is_new_user: true`)와 함께 JWT 반환
- **에러 상태:** 
  - `401 Unauthorized`: 만료되었거나 신뢰할 수 없는 구글 토큰일 때 ("Invalid social token")
  - `500 Internal Server Error`: 외부 구글 API 통신 실패 시

### B-02 유저 프로필 관리

- **트리거 (프론트 요청):** 마이페이지 진입 시 정보 노출 또는 개인 프로필 수정 후 저장 시 호출
- **제공 API:** 
  - 프로필 조회: `GET /api/users/me/`
  - 프로필 수정: `PATCH /api/users/me/`
- **입력 데이터:** (PATCH 요청 시) `{ "nickname": "string (선택)", "profile_image_url": "string (선택)" }`
- **성공 시 처리 (Response):** `200 OK`. 수정 사항을 유저 테이블에 업데이트하고 최신 유저 객체 반환 (`{ "id": 1, "email": "test@example.com", "nickname": "김멋사", "profile_image_url": "..." }`)
- **에러 상태:**
  - `401 Unauthorized`: JWT 토큰이 유효하지 않거나 비어있는 경우
  - `400 Bad Request`: 닉네임 글자수 초과시

### B-03 에타 시간표 URL 파싱

- **트리거 (프론트 요청):** 시간표 등록 단계에서 에브리타임 URL을 기입하고 "다음" 클릭 시 호출
- **제공 API:** `POST /api/timetables/upload-url/`
- **입력 데이터:** `{ "url": "https://everytime.kr/@..." }`
- **성공 시 처리 (Response):** `200 OK`. 백엔드에서 해당 URL을 토대로 API에 요청 후 파싱하여 강의명, 요일, 시작/종료 시간을 추출함. 기존 데이터가 존재하면 덮어쓰기(Overwrite) 후 저장하며 파싱 완료된 수업 수 응답 반환 (`{ "status": "success", "parsed_classes_count": 5 }`)
- **에러 상태:**
  - `400 Bad Request`: 제공된 URL 형식이 에브리타임 공식 주소가 아니거나 도메인이 다른 경우
  - `422 Unprocessable Entity`: 시간표가 비어 있거나 비공개인 경우. 기존 수업은 유지
  - `502 Bad Gateway`: 에브리타임 서버 측 문제 등으로 데이터를 읽어올 수 없는 경우

### B-04 등록 수업 관리

- **트리거 (프론트 요청):** 시간표 등록 화면에서 등록된 수업을 확인하거나 삭제할 때 호출
- **제공 API:**
  - 수업 목록 조회: `GET /api/timetables/classes/`
  - 수업 전체 삭제: `DELETE /api/timetables/classes/`
  - 수업 개별 삭제: `DELETE /api/timetables/classes/{id}/`
- **성공 시 처리 (Response):** 조회는 `200 OK`와 수업 목록(요일·시작 시간 순), 삭제는 `204 No Content`. 확정 모임으로 생긴 항목은 포함하지 않음
- **에러 상태:**
  - `401 Unauthorized`: 인증되지 않은 요청
  - `404 Not Found`: 없는 수업이거나 다른 사용자의 수업인 경우

### B-05 고정 일정 CRUD

- **트리거 (프론트 요청):** 고정 일정 관리 화면에서 정기 일정을 조회, 추가, 또는 삭제하고자 할 때 호출
- **제공 API:**
  - 고정 일정 등록: `POST /api/schedules/fixed/`
  - 고정 일정 조회: `GET /api/schedules/fixed/`
  - 고정 일정 삭제: `DELETE /api/schedules/fixed/{id}/`
- **입력 데이터:** (POST 요청 시) `{ "title": "동아리", "repeat_days": ["MON", "THU"], "start_time": "19:00", "end_time": "21:00" }`
- **성공 시 처리 (Response):** 
  - 등록: `201 Created`. 반복 일정 데이터를 저장하고 등록된 레코드 반환
  - 조회: `200 OK`. 해당 유저가 등록한 고정 일정 리스트 반환
  - 삭제: `204 No Content`. 대상 레코드를 하드/소프트 딜리트 처리 후 무응답 반환
- **에러 상태:** 
  - `400 Bad Request`: 종료 지정 시각이 시작 지정 시각보다 이른 경우, 혹은 요일 포맷 무결성이 깨진 경우
  - `404 Not Found`: 삭제하려는 일정 고유 ID가 DB에 없는 경우

### B-06 통합 시간표 데이터 조회

- **트리거 (프론트 요청):** 대시보드의 주간 캘린더를 그리거나, 모임 일정을 새로 조율할 때 개인의 이용 불가 시간 타임라인을 조회하기 위해 호출
- **제공 API:** `GET /api/timetables/consolidated/`
- **입력 데이터:** 없음 (Header: `Authorization` JWT 전달)
- **성공 시 처리 (Response):** `200 OK`. 유저의 공식 학기 시간표 데이터와 수동 등록한 알바/동아리 등 고정 일정을 요일 기준으로 쿼리 및 병합(Merge) 연산하여 중복 시간을 제거한 주간 타임라인 최종본 반환 (`{ "MON": [{ "start": "09:00", "end": "12:00" }], ... }`)
- **예외/데이터 없음:** 등록된 일정 정보가 아예 없는 경우 빈 요일 키 리스트 반환 (`{ "MON": [], "TUE": [], ... }`)

### B-07 모임 생성 및 링크 생성

- **트리거 (프론트 요청):** 모임 개설자가 입력 폼을 다 채운 뒤 생성 제출 클릭 시 호출
- **제공 API:** `POST /api/meetings/`
- **입력 데이터:** `{ "name": "중간발표 준비", "purpose": "조용한 회의", "desired_time": "주중 오후", "desired_location": "학생회관 1층 회의실", "latitude": 37.123456, "longitude": 127.123456, "capacity": 4 }`
- **성공 시 처리 (Response):** `201 Created`. 신규 모임 레코드를 저장하고 해당 유저에게 모임장 권한을 부여함. 공유용 초대 링크를 생성하기 위해 암호화 유효 토큰을 발급하여 매핑 후 반환 (`{ "meeting_id": 10, "invite_link": "https://...", "token": "..." }`)
- **에러 상태:** `400 Bad Request` (정원이 최솟값 2명 미만이거나 모임명 글자 수 제한 초과 시)

### B-08 모임 참여 처리

- **트리거 (프론트 요청):** 초대 링크로 들어온 사용자가 자신의 참여 희망 조건을 기재하고 제출 시 호출
- **제공 API:** `POST /api/meetings/invite/{token}/join/`
- **입력 데이터:** `{ "desired_time": "주중 오후", "desired_location": "학생회관", "latitude": 37.123456, "longitude": 127.123456}`
- **성공 시 처리 (Response):** `200 OK`. 패스 토큰 유효성 및 만료 여부를 검사하고 현재 인원수가 모임 정원 이내인지 확인함. 유효하면 해당 사용자의 기본 시간표 데이터 스냅샷 및 개별 희망 사항 정보를 결합 저장하고 성공 응답 반환
- **에러 상태:**
  - `404 Not Found`: 일치하는 모임 토큰이 없거나 파기된 초대 링크일 때
  - `409 Conflict`: 모임 참여 정원이 이미 가득 찬 경우

### B-09 모임 초대 정보 조회
- **트리거 (프론트 요청):** 사용자가 외부에서 공유받은 초대 링크로 진입하여 참여 화면(F-10)을 처음 렌더링할 때 호출
- **제공 API:** `GET /api/meetings/invite/{token}/`
- **성공 시 처리 (Response):** `200 OK`. 초대 토큰의 유효성을 검증한 후, 모임에 가입하기 전 화면에 보여줄 모임 메타데이터와 현재 참여 중인 멤버들의 리스트 정보를 반환 (`{"meeting_id": 10,"meeting_name": "중간발표 준비","purpose": "조용한 회의","creator_name": "김멋사","current_participants_count": 2,"capacity": 4,"existing_members": [{ "nickname": "김멋사", "profile_image_url": "..." },{ "nickname": "박준석", "profile_image_url": "..." }]}`)
- **에러 상태:**
  - `404 Not Found`: 유효하지 않거나 기간이 만료되어 파기된 초대 토큰일 때

### B-10 모임 리스트 및 상세 조회

- **트리거 (프론트 요청):** 모임 관리 탭 클릭 시 및 특정 모임 카드를 터치했을 때(상세) 호출
- **제공 API:** 
  - 목록: `GET /api/meetings/?status={active|ended}`
  - 상세: `GET /api/meetings/{id}/`
- **성공 시 처리 (Response):** 
  - 목록: `200 OK`. 유저 정보 기반 필터링된 모임 리스트(이름, 방장여부, 참여수 등) 전달
  - 상세: `200 OK`. 모임 기획 메타데이터, 참여 중인 총 멤버들의 요약 리스트(이름, 역할 등)
- **예외/데이터 없음:** 목록 조회 시 참여 중인 모임 리스트가 전무할 경우 빈 배열(`[]`) 응답
- **에러 상태:** `403 Forbidden` (본인이 참가자로 소속되지 않은 타 모임 ID를 임의로 쿼리할 때)

### B-11 모임 정보 수정 및 탈퇴
- **트리거 (프론트 요청):** 모임 상세 페이지에서 모임장이 모임 정보를 변경하거나, 구성원이 모임방에서 나가기를 클릭했을 때 호출
- **제공 API:** 
  - 모임 정보 수정: `PATCH /api/meetings/{id}/`
  - 모임 탈퇴/삭제: `DELETE /api/meetings/{id}/`
- **성공 시 처리 (Response):**
  - 수정: `200 OK`. 변경된 모임 정보 객체 반환
  - 탈퇴/삭제: `204 No Content`. 일반 구성원이면 모임 참여 매핑 데이터를 삭제(탈퇴)하고, 모임장일 경우 모임방 자체를 삭제 처리 후 무응답 반환
- **에러 상태:**
  - `403 Forbidden`: 모임 정보 수정 권한이 없는 유저가 수정을 시도할 때

### B-12 AI 일정 추천 알고리즘

- **트리거 (프론트 요청):** 모임 상세 페이지에서 AI 분석 결과창으로 넘어갈 때 계산 요청을 위해 호출
- **제공 API:** `GET /api/meetings/{id}/recommendations/`
- **성공 시 처리 (Response):** `200 OK`. 해당 모임 고유 ID에 연관 등록된 모든 참여자들의 병합 시간표(B-06)를 행렬 데이터로 치환 후 겹치는 시간 연산 알고리즘 구동. 가장 긴 공통 공강 지점을 기준으로 후보군 정렬 후 후보 시간 리스트 반환
- **예외/데이터 없음:** 참여 인원이 부족하여 분석을 돌릴 수 없는 경우 알고리즘을 바이패스하고 `{ "can_recommend": false, "reason": "LACK_OF_PARTICIPANTS" }` 반환

### B-13 추천 결과 상세 사유 생성

- **트리거 (프론트 요청):** B-10 연산 프로세스 내부 또는 연계 단계에서 후보 일정들의 맥락 분석을 추가 제공하기 위해 동작
- **제공 API:** `GET /api/meetings/{id}/recommendations/` (B-10 API의 하위 상세 객체 영역에 포함)
- **성공 시 처리 (Response):** `200 OK`. 추출된 추천 시각 후보를 기반으로, 참가자들의 해당 요일 수업 정보와 희망 장소 간의 지리적 이동 시각을 가중치 행렬로 검사함. GPT-5 Nano 등 소형 LLM 파이프라인 혹은 사전 룰 기반 판별기에 문맥을 정렬 전송하여 사유 텍스트 배열을 채워 응답 처리 (`"reason_bullets": ["4명 모두 가능", "이동 시간이 짧은 시간", "집중하기 좋은 시간대"]`)

### B-14 모임 일정 확정

- **트리거 (프론트 요청):** 모임장이 AI 추천 결과 1, 2순위 중 특정 시간을 최종 모임 시간으로 확정하기 클릭 시 호출
- **제공 API:** `POST /api/meetings/{id}/confirm/`
- **입력 데이터:** `{ "selected_recommendation_id": 1 }`
- **성공 시 처리 (Response):** `200 OK`. 모임 레코드의 상태 필드를 `CONFIRMED`로 변경하고 최종 조율 일정 정보 고정. 모임 참여 유저 전원의 개별 시간표 뷰에 해당 일정 블록을 확정 일정으로 동기화 갱신하고 상태 응답 반환
- **에러 상태:**
  - `403 Forbidden`: 모임장 권한이 없는 일반 구성원이 모임 시간을 강제 확정하려 할 때
  - `404 Not Found`: 전달받은 모임 ID 또는 추천 시간 ID 레코드가 없을 때

### B-15 확정된 모임 정보 조회

- **트리거 (프론트 요청):** 일정 확정 완료 페이지(F-13) 진입 시, 확정된 모임 일정과 참가 확정 멤버 정보의 확인을 위해 호출

- **에러 상태:**
  - `403 Forbidden`: 해당 모임에 참여 권한이 없는 유저가 조회를 시도하는 경우
  - `404 Not Found`: 해당 ID의 모임이 존재하지 않거나, 아직 상태가 확정(`CONFIRMED`) 단계가 아닌 경우

### F-06 네비게이션 바 및 라우팅

- **사용자 동작:** 하단 글로벌 탭(홈, 모임, 캘린더, 알림, 마이) 영역의 특정 아이콘 클릭
- **호출 API:** 없음 (프론트엔드 라우터 및 상태 관리 엔진 내부 전환)
- **성공 시 UI:** 선택된 탭 아이콘의 색상이 활성화 톤으로 변경되며 해당 타겟 페이지(F-05, F-07, F-14 등)로 부드러운 전환 효과 적용
- **에러 상태:** 페이지 로드 실패 시 "잘못된 경로이거나 로딩 오류입니다." 문구가 포함된 대체 페이지 출력

### F-07 모임 목록 조회 및 필터링

- **사용자 동작:** 메인 또는 네비게이션의 '모임' 버튼 클릭 진입 → 상단 탭 '참여 중' / '종료된 모임' 선택 전환
- **호출 API:** `GET /api/meetings/?status={active|ended}`
- **성공 시 UI:** 해당 상태의 모임 목록 카드(모임명, 참여 인원 정보, AI 다음 추천 예정일 등) 리스트가 최신순으로 정렬되어 노출
- **빈 상태:** "해당되는 모임이 없습니다." 이미지/텍스트 안내와 화면 하단 고정된 "+ 모임 만들기" 버튼 렌더링
- **에러 상태:** "모임 목록을 가져오는 데 실패했습니다. 아래로 당겨서 새로고침 해주세요." 문구 노출

### F-08 모임 생성 단계 폼

- **사용자 동작:** 화면 하단 "+ 모임 만들기" 버튼 클릭 → 각 세부 설정 항목 작성 후 "초대 링크 생성" 버튼 클릭
- **입력 항목:** 모임 이름(필수, 1~20자), 모임 목적(필수, 드롭다운 선택), 희망 시간대(선택, 드롭다운 선택), 희망 장소(선택, 직접 입력 또는 좌표 선택 연동), 정원(필수, 드롭다운 선택)
- **호출 API:** `POST /api/meetings/` (body: `{name, purpose, desired_time, desired_location, capacity}`)
- **성공 시 UI:** 모임 생성 완료 팝업 표출 -> 팝업 내부 '초대 링크 복사' 버튼 활성화 및 복사 완료 토스트 안내 -> 닫기 시 모임 상세 화면(F-11)으로 이동
- **검증 실패:** 필수 값(이름, 목적, 정원) 누락 시 해당 항목 테두리 적색 하이라이트 및 "필수 정보를 기입해 주세요." 안내 문구 출력

### F-09 위치 좌표 선택 인터페이스

- **사용자 동작:** 모임 생성(F-08) 또는 모임 참여(F-10) 폼 내에서 "위치 좌표로 선택하기" 버튼 클릭
- **호출 API:** 카카오맵 SDK 로드
- **성공 시 UI:** 카카오맵 지도 팝업 모달 노출 -> 핀 드래그&드롭 혹은 장소 검색어 입력 후 "장소 선택 완료" 클릭 시 장소 명칭과 고유 좌표 데이터가 모임 입력 필드(희망 장소)에 자동 주입되고 모달 종료
- **에러 상태:** 지도 로딩 지연 혹은 SDK 호출 오류 시 "지도 데이터를 불러오는 중에 오류가 발생했습니다. 잠시 후 다시 시도해 주세요." 토스트 안내

### F-10 모임 참여(초대 페이지) 폼

- **사용자 동작:** 모임 외부 초대 링크 클릭 진입 -> 모임 개요 및 명단 확인 후 본인의 희망 조건 입력 후 "제출하기" 버튼 클릭
- **입력 항목:** 희망 시간대(필수, 드롭다운 다중 선택 가능), 희망 장소(선택, 직접 입력 및 F-09 연동)
- **호출 API:** 
  - 모임 정보 로드: `GET /api/meetings/invite/{token}/`
  - 참여 양식 제출: `POST /api/meetings/invite/{token}/join/` (body: `{desired_time, desired_location}`)
- **성공 시 UI:** "참여 신청이 성공적으로 제출되었습니다." 토스트 알림 노출 후 해당하는 모임 상세(F-11) 화면으로 전환
- **검증 실패:** 필수 조건인 희망 시간 미지정 후 제출 클릭 시 "참여를 완료하려면 희망 일정을 1개 이상 선택해 주세요." 유효성 경고 노출

### F-11 모임 상세 및 관리 화면

- **사용자 동작:** 모임 목록에서 특정 모임 카드 터치 시 자동 호출 및 진입
- **호출 API:** `GET /api/meetings/{id}/`
- **성공 시 UI:** 모임 기본 정보 카드(목적, 희망 시간, 희망 장소), 현재까지 참여 완료된 총인원 목록(방장 표시 분리), "+ 멤버 초대" 및 "모임 정보 수정" 액션 버튼 노출
- **권한 처리:** 모임장(생성자)이 아닐 경우 "모임 정보 수정" 버튼 비활성화 처리
- **에러 상태:** 모임 세션 유실 혹은 네트워크 통신 실패 시 "정보를 찾을 수 없거나 이미 파기된 모임방입니다." 페이지 안내

### F-12 AI 추천 결과 카드 및 확정

- **사용자 동작:** 모임 상세(F-11)에서 최적 추천 시간 영역을 터치하거나 추천 버튼 진입 시 노출 -> 추천 후보군 카드 중 특정 카드의 "이 시간으로 확정" 클릭
- **호출 API:** 
  - 추천 리스트 가져오기: `GET /api/meetings/{id}/recommendations/`
  - 최종 시간 확정 처리: `POST /api/meetings/{id}/confirm/` (body: `{selected_recommendation_id}`)
- **성공 시 UI:** 1순위, 2순위 추천 카드가 상단에 배치되고 하단에 추천 근거(모든 인원 동선 최소화, 수업 시간 연접성 등) 텍스트 렌더링 → 확정 API 성공 응답 수신 시 일정 확정 완료 페이지(F-13)로 화면 라우팅
- **빈 상태:** 아직 참여 멤버들의 조건이 충족되지 않은 상황일 경우 "최소 정원 이상이 수집되어야 AI 최적 분석 결과가 노출됩니다." 경고 뷰 렌더링
- **에러 상태:** "분석 연산 중 서버 에러가 발생했습니다. 다시 시도해 주세요." 에러 배너 노출

### F-13 일정 확정 완료 화면

- **사용자 동작:** 모임 일정 확정이 완료되는 즉시 자동으로 랜딩되는 전용 정보 페이지
- **호출 API:** `GET /api/meetings/{id}/confirmed/`
- **성공 시 UI:** 체크 애니메이션과 함께 최종 조율 완료된 대표 날짜 및 시간 영역을 강조된 전용 컴포넌트로 시각화, 참여 확정 멤버 정보 렌더링, "모임 상세로 이동" 버튼 상시 제공
- **에러 상태:** 확정 정보 로드 실패 시 기본 캘린더 동기화 유도가 불가능하므로, "잠시 후 상세 페이지에서 확정 상태를 조회해 주세요." 모달 팝업 가이드 노출

### F-14 마이페이지 메뉴 구성

- **사용자 동작:** 네비게이션 '마이' 탭 클릭 시 자동 진입
- **호출 API:** `GET /api/users/me/`
- **성공 시 UI:** 최상단 사용자 프로필 요약 카드 정보 매핑(닉네임, 이메일 주소 등) 및 하단 세부 제어 메뉴 리스트(시간표 관리, 고정 일정 관리, 알림 설정, 로그아웃) 렌더링
- **로그아웃 처리:** "로그아웃" 클릭 시 한 번 더 물어보기 -> 동의 시 스토리지 토큰 삭제 및 첫 로그인 화면(F-02)으로 이동

### F-15 알림 내역 화면
- **사용자 동작:** 하단 네비게이션 바에서 '알림' 탭 아이콘 터치 시 진입
- **호출 API:** 
  - 알림함 조회: `GET /api/notifications/`
  - 알림 개별 읽음 처리: `POST /api/notifications/read/{id}/`
- **성공 시 UI:** 
  - 유저 앞으로 수신된 알림 목록(모임 초대 등록, 일정 확정 안내 등)을 최신순 리스트 형태로 렌더링
  - 읽지 않은 알림은 좌측에 강조 표시를 띄우고, 터치 시 읽음 처리 API를 호출하여 시각적으로 읽음 상태로 즉시 변경
- **빈 상태:** 수신된 알림이 없을 경우 "아직 도착한 알림이 없습니다." 안내 텍스트 노출

#### F-16 캘린더 화면
- **사용자 동작:** 하단 네비게이션 바에서 '캘린더' 탭 아이콘 터치 시 진입
- **호출 API:** `GET /api/timetables/consolidated/`
- **성공 시 UI:** 
  - 개인의 월간/주간 캘린더 뷰 렌더링
  - 에브리타임 기본 시간표와 수동 등록한 고정 일정(B-05), 그리고 최종 확정 완료된 모임 일정들이 서로 다른 색상의 블록 형태로 통합 시각화되어 노출됨
- **에러 상태:** 일정 데이터를 불러오지 못했을 때 화면 하단에 "캘린더 정보를 동기화하지 못했습니다." 토스트 안내 노출
